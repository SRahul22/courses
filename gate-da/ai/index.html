    AI: search, logic and reasoning under uncertainty

    The AI section is small and very predictable: 6 to 10 marks a year from three ideas. Search asks which node is expanded next and whether a heuristic is admissible; logic asks whether a sentence is a tautology or says what an English sentence says; Bayesian networks ask for a probability or a conditional independence. This module teaches each idea on small examples from the Data Premier League and then works through every DA AI question asked so far.

    The route

      A lot of AI comes down to one question: given where you are and where you want to be, which sequence of moves gets you there? This part teaches you to see a problem as a map of situations, explores that map blindly (breadth-first, depth-first, uniform-cost), then with a sense of direction (greedy and A*), and finally against an opponent who wants you to lose (minimax and alpha–beta pruning). Search has appeared in every GATE DA paper so far, often with a figure to trace by hand.

      You need: what a graph is, and queues and stacks, from Python & DSA. Nothing else; every AI term is defined here.

      Uninformed search: finding a route with no sense of direction

      Uninformed (or “blind”) search explores a map of possible situations in a fixed order, using only the map itself and never a guess about how close the goal is.

      GATE DA asks which algorithm is uninformed (2026 Q13), and every A* or game-tree question builds on the same ideas: frontier, expansion, path cost. The properties table in this chapter (complete? optimal? how much memory?) is a favourite source of one-mark questions.

      It’s like looking for your friend’s seat in a stadium without a ticket number: you can sweep row by row, or run down one aisle to the end before trying the next, but you have no clue which direction is warmer.

      The problem: the team bus

      The Bengaluru Backprops have an away match against the Kalinga Kernels in Bhubaneswar. Their team bus has a route planner: a program that looks at the road map and decides which roads to drive. That route planner is our first agent.

      An agent is anything that observes its situation and chooses actions. A chess program, a delivery robot and the bus’s route planner are all agents. The agents in this chapter plan the whole sequence of actions in their head first, then carry it out.

      A search problem has five parts. Each is shown with the bus example.

      • States: every situation the world can be in, described just well enough to plan. Bus: which city it is in (8 cities, so 8 states).
      • Initial state: where you start. Bengaluru.
      • Actions: what you can do in a state. In Hyderabad: drive to Bengaluru, Vijayawada, Nagpur or Raipur.
      • Goal test: a check that says whether a state is a goal. “Is the bus in Bhubaneswar?”
      • Path cost: a number for each sequence of actions, the sum of the step costs. Total hours on the road.

      The state space is the graph whose nodes are states and whose edges are actions, labelled with their step costs. A solution is a path from the initial state to a goal state; an optimal solution is one with the smallest path cost.

      So “searching a state space” is a precise phrase: walk around this graph, starting at the initial state, until you find a path to a goal. For the bus the state space is just the road map. For other problems it is far larger and never drawn in full: in a puzzle, each arrangement of the pieces is one state.

      Frontier and expansion: the one idea behind every algorithm

      Every search algorithm in this part keeps two collections:

      • the frontier: states you have discovered (you know a path to them) but have not yet explored from;
      • the explored set (or closed set): states you have already explored from.

      To expand a state means to take it out of the frontier, check whether it is a goal, and if not, put its neighbours (its children, or successors) into the frontier. Start with only the initial state in the frontier and repeat until you expand a goal or the frontier is empty.

      That loop never changes. The only difference between BFS, DFS, uniform-cost search and A* is which state comes out of the frontier next.

      1. frontier ← {initial state}; explored ← empty.
      2. Repeat: if the frontier is empty, report failure. Remove one state $n$ from the frontier (the choice rule defines the algorithm).
      3. If $n$ passes the goal test, return the path to $n$.
      4. Add $n$ to explored. For each child of $n$ that is in neither the frontier nor explored, add it to the frontier and remember $n$ as its parent.

      Without the explored set this is called tree search: it may revisit states and can loop forever on a map with cycles.

      Depth-limited search and iterative deepening

      DFS uses very little memory: it only holds the current path and the unexplored siblings along it. But on a huge or infinite state space it can dive forever down one branch. Two fixes:

      • Depth-limited search (DLS): DFS that treats every state at depth $\ell$ (the depth limit) as if it had no children. It cannot go forever, but if the shallowest goal is deeper than $\ell$ it fails.
      • Iterative deepening DFS (IDDFS): run DLS with $\ell = 0, 1, 2, \ldots$ until a goal is found. It finds the shallowest goal like BFS but needs only DFS’s memory.

      Doesn’t IDDFS waste time redoing the top of the tree? Very little: almost all the nodes of a tree are in its bottom level, which IDDFS generates only once.

      Informed search: heuristics, greedy best-first and A*

      Informed search uses a heuristic, a cheap estimate of the cost still to go, to expand the most promising states first; A* combines it with the cost already paid and still guarantees the cheapest route.

      A* is the most examined search topic in GATE DA: tracing its expansion order (2025 Q44, sample Q27) and knowing which heuristics are admissible (2024 Q23, sample Q46). Expect at least one question, often two marks.

      It’s like driving with a sign that says “Bhubaneswar 600 km” at each junction: you still count the kilometres you have driven, but the signs stop you wandering south.

      Uniform-cost search found the bus’s best route, but it expanded every city cheaper than 23 hours, including Nagpur and Raipur, which are in the wrong direction for a good route. It had no idea where Bhubaneswar was.

      Suppose the planner also knows, for each city, a rough estimate of the hours still needed, say from the straight-line distance. Bengaluru is about 15 hours away, Visakhapatnam about 5. That estimate is a heuristic.

      A heuristic function $h(n)$ estimates the cost of the cheapest path from state $n$ to a goal. It must be cheap to compute and $h(\text{goal}) = 0$. Write $h^*(n)$ for the true cheapest cost from $n$ to a goal. Example: on the bus map $h(\text{VTZ}) = 5$ while $h^*(\text{VTZ}) = 6$.

      Both use the generic graph search with a priority queue; only the priority differs.

      Greedy best-first search: expand the state with the smallest $h(n)$. It heads straight for whatever looks closest.

      A* search: expand the state with the smallest $$f(n) = g(n) + h(n),$$ where $g(n)$ is the cost already paid to reach $n$. So $f(n)$ estimates the cost of the cheapest complete route through $n$. With $h = 0$ everywhere, A* is uniform-cost search.

      $h$ is admissible if it never overestimates: $h(n) \le h^*(n)$ for every state $n$. Straight-line distance is admissible for road travel: no road is shorter than the straight line.

      $h$ is consistent (or monotone) if for every edge $n \to n'$ with cost $c(n, n')$: $$h(n) \le c(n, n') + h(n').$$ This is a triangle inequality: your estimate cannot drop by more than the step you just paid for. Every consistent heuristic (with $h(\text{goal}) = 0$) is admissible; the converse is false.

      A* tree search returns an optimal solution if $h$ is admissible. A* graph search (with an explored set, never reopening closed states) returns an optimal solution if $h$ is consistent. With a consistent $h$, the $f$-values of expanded states never decrease.

      Why admissibility is enough for tree search, in two lines. Let $C^*$ be the optimal cost. Some state $n$ on the optimal route is always waiting in the frontier with $f(n) = g(n) + h(n) \le g(n) + h^*(n) = C^*$. A worse goal $G_2$ has $f(G_2) = g(G_2) \gt C^*$, so $n$ always comes out first, and A* cannot return $G_2$ before finishing the optimal route.

      For graph search, admissibility is not enough: A* may close a state via an expensive path and then never reopen it. The Try it below shows exactly this.

      Adversarial search: minimax and alpha–beta pruning

      Adversarial search plans moves when an opponent moves too: minimax assumes the opponent always picks the reply that is worst for you, and alpha–beta pruning gets the same answer while skipping branches that cannot matter.

      The problem: two captains

      Before the final, the Kalinga Kernels’ captain picks one of three batting plans. The Hyderabad Hyperplanes’ captain sees the plan and picks one of three bowling plans in reply.       A route planner chooses every step itself. Here half the choices belong to someone working against you. That changes the question from “which path is best?” to "which move is best, assuming the reply is as bad for me as possible?"

      A two-player, turn-taking, zero-sum game (one player’s gain is the other’s loss) with perfect information is drawn as a game tree:

      • The root is the current position; levels alternate between the player MAX (wants a high score) and the opponent MIN (wants it low). One level of moves is a ply.
      • Leaves (terminal states) carry a utility: the final score from MAX’s point of view. Kernels’ winning margin: MAX = Kernels, MIN = Hyperplanes.

      The minimax value of a node is: its utility, if it is a leaf; the largest value among its children, if MAX moves there; the smallest, if MIN moves there. Compute it bottom-up (by a depth-first walk). At the root, MAX plays the move leading to the child with the largest value.

      Minimax visits every node: time $O(b^m)$ for branching factor $b$ and depth $m$, memory $O(bm)$.

      Alpha–beta pruning: skip what cannot matter

      In the “DPL match” tree of the Try it below, the Kernels’ first plan B leads to margins 3, 12, 8; the Hyperplanes would choose 3, so plan B is worth 3. Now the Kernels look at plan C. The first reply gives margin 2. Stop right there: whatever the other two replies give, the Hyperplanes can hold plan C to at most 2, and the Kernels already have 3. The remaining leaves under C can be skipped without being looked at.

      Alpha–beta pruning formalises this with two numbers carried down the tree.

      At any point of the depth-first walk:

      • $\alpha$ = the highest value MAX is already guaranteed at some choice point on the path from the root (MAX’s best option so far). It starts at $-\infty$ and only rises at MAX nodes.
      • $\beta$ = the lowest value MIN is already guaranteed on the path (MIN’s best option so far). It starts at $+\infty$ and only falls at MIN nodes.

      Values between $\alpha$ and $\beta$ are the only ones that can still change the decision. As soon as $\alpha \ge \beta$ at a node, its remaining children are pruned: one of the players above will never let play reach this node.

      Walk the tree left to right, depth first, passing $(\alpha, \beta)$ down.
      At a MAX node: after each child returns value $v$, set $\alpha \leftarrow \max(\alpha, v)$. If $\alpha \ge \beta$, prune its remaining children.
      At a MIN node: after each child returns value $v$, set $\beta \leftarrow \min(\beta, v)$. If $\alpha \ge \beta$, prune its remaining children.
      A node passes its value up to its parent; the parent’s $\alpha$ and $\beta$ were never changed by the child.

      A truth table lists every way of giving T or F to the atoms, one row each, and works out the sentence in each row. With $n$ atoms there are $2^n$ rows: 4 rows for $p, q$; 8 for $p, q, r$. A row is also called a model (or a possible world): one complete description of how things could be.

      The connective everyone trips on: "if $p$ then $q$"

      Treat $p \Rightarrow q$ as a promise. The league announces: “If it rains, the match will be shortened.” Four things can happen.

      Rain ($p$)Shortened ($q$)Was the promise kept?$p \Rightarrow q$

      TFNo: it rained and they played the full match. The only broken promise.F

      The last two rows are the ones that feel odd. "If $p$ then $q$" only makes a claim about the situations where $p$ happens. When $p$ is false, the promise was never tested, and logic counts an untested promise as kept. We say $p \Rightarrow q$ is vacuously true when $p$ is false.

      Two consequences worth remembering. First, $p \Rightarrow q$ has exactly one false row ($p$ true, $q$ false), so it says the same as "not ($p$ and not $q$)", which is $\lnot p \lor q$. Second, $p \Rightarrow q$ does not say that $p$ causes $q$, or that $p$ happens at all; it only rules out "$p$ without $q$".

      Careful: $p \Rightarrow q$ is not the same as its converse $q \Rightarrow p$. “If it rains, the match is shortened” does not mean “if the match is shortened, it rained”. It is the same as its contrapositive $\lnot q \Rightarrow \lnot p$: “if the match was not shortened, it did not rain”.

      A sentence is a tautology (or valid) if it is true in every row of its truth table, e.g. $p \lor \lnot p$. It is a contradiction (or unsatisfiable) if it is false in every row, e.g. $p \land \lnot p$. It is satisfiable if it is true in at least one row.

      Two sentences $F$ and $G$ are logically equivalent, written $F \equiv G$, if they have the same value in every row. Equivalently, $F \Leftrightarrow G$ is a tautology.

      Each one can be checked with a four- or eight-row truth table.

      • Implication: $p \Rightarrow q \;\equiv\; \lnot p \lor q$.
      • Contrapositive: $p \Rightarrow q \;\equiv\; \lnot q \Rightarrow \lnot p$.
      • Negated implication: $\lnot(p \Rightarrow q) \;\equiv\; p \land \lnot q$.
      • Biconditional: $p \Leftrightarrow q \;\equiv\; (p \Rightarrow q) \land (q \Rightarrow p)$.
      • De Morgan: $\lnot(p \land q) \equiv \lnot p \lor \lnot q$ and $\lnot(p \lor q) \equiv \lnot p \land \lnot q$ (the same laws as for sets: complement of an intersection is the union of complements).
      • Distributive: $p \lor (q \land r) \equiv (p \lor q) \land (p \lor r)$ and $p \land (q \lor r) \equiv (p \land q) \lor (p \land r)$.
      • Double negation: $\lnot\lnot p \equiv p$.

      Entailment: what the knowledge base guarantees

      Back to the assistant. Its knowledge base is the “and” of all its sentences. A sentence $\alpha$ (the Greek letter alpha, standing for any sentence) is entailed by the knowledge base, written $KB \models \alpha$, if $\alpha$ is true in every model in which $KB$ is true. In words: whenever everything the agent knows holds, $\alpha$ must hold too. The symbol $\models$ is read “entails”.

      The following say the same thing:

      1. $KB \models \alpha$: every row where $KB$ is true also makes $\alpha$ true.
      2. $KB \Rightarrow \alpha$ is a tautology.
      3. $KB \land \lnot\alpha$ is unsatisfiable (no row makes $KB$ true and $\alpha$ false).

      The third form is the one computers use: to prove $\alpha$, assume it is false and show that this clashes with the knowledge base.

      Two inference rules come up all the time. Modus ponens: from $p$ and $p \Rightarrow q$, conclude $q$ (that’s what the assistant did twice). Modus tollens: from $p \Rightarrow q$ and $\lnot q$, conclude $\lnot p$. A tempting but unsafe pattern is "from $q$ and $p \Rightarrow q$, conclude $p$" (affirming the consequent): the match may have been shortened for another reason.

      CNF and resolution: how a program proves things

      Truth tables double with every new atom (30 atoms means over a billion rows), so real reasoners use rules instead. The most common is resolution, and it works on sentences in a standard shape.

      A literal is an atom or its negation ($p$ or $\lnot p$). A clause is an “or” of literals, like $\lnot p \lor q \lor r$. A sentence is in conjunctive normal form (CNF) if it is an “and” of clauses, like $(\lnot p \lor q) \land (p \lor r)$.

      1. Replace $p \Leftrightarrow q$ by $(p \Rightarrow q) \land (q \Rightarrow p)$.
      2. Replace $p \Rightarrow q$ by $\lnot p \lor q$.
      3. Push every $\lnot$ inwards with De Morgan’s laws and $\lnot\lnot p \equiv p$, until $\lnot$ sits only on atoms.
      4. Distribute $\lor$ over $\land$: $p \lor (q \land r)$ becomes $(p \lor q) \land (p \lor r)$.

      Resolution rule: from two clauses that contain a complementary pair, such as $(a \lor b)$ and $(\lnot b \lor c)$, infer the clause with that pair removed: $(a \lor c)$. If $b$ is true, $c$ must hold; if $b$ is false, $a$ must hold; either way $a \lor c$.

      To show $KB \models \alpha$: put $KB \land \lnot\alpha$ in CNF, then keep resolving pairs of clauses. If you reach the empty clause (written $\square$, from resolving $b$ with $\lnot b$), $KB \land \lnot\alpha$ is unsatisfiable, so $KB \models \alpha$.

      The assistant’s reasoning as resolution: let $a$ = rain, $b$ = shortened, $c$ = extra spinner. The KB in CNF is $(\lnot a \lor b)$, $(\lnot b \lor c)$, $(a)$. To prove $c$, add $\lnot c$. Resolve $(\lnot b \lor c)$ with $(\lnot c)$: $(\lnot b)$. Resolve that with $(\lnot a \lor b)$: $(\lnot a)$. Resolve that with $(a)$: the empty clause. So $KB \models c$.

      Why propositions are not enough

      Suppose the Kalinga Kernels’ assistant has to know that every batter in a 25-player squad is fit. In propositional logic each fact needs its own atom: $\mathit{AshaFit}$, $\mathit{BilalFit}$, and so on, and the rule “batters must be fit” has to be written 25 times. Add a player and you add atoms and rules. Worse, the logic cannot see that $\mathit{AshaFit}$ and $\mathit{BilalFit}$ are about the same property.

      First-order logic (also called predicate logic) fixes this by talking about objects and their properties.

      The vocabulary
      domain
      the set of objects we talk about, e.g. the four players Asha, Bilal, Chitra, Dev. It is never empty.
      constant
      a name for one object: $\mathit{Asha}$.
      variable
      a placeholder for an object: $x$, $y$.
      predicate
      a property or relation that is T or F once you plug in objects: $\mathit{Fit}(x)$ “x is fit”, $\mathit{Admires}(x, y)$ “x admires y”.
      $\forall x$
      "for all $x$": the sentence after it holds for every object in the domain.
      $\exists x$
      "there exists $x$": it holds for at least one object (one or more).

      A world (also called an interpretation or model) fixes the domain and says, for each predicate, which objects it is true of. “Every batter is fit” is then written once: $$\forall x\,\big(\mathit{Batter}(x) \Rightarrow \mathit{Fit}(x)\big).$$ Over a finite domain, $\forall$ is a big “and” and $\exists$ is a big “or”: with the four players, $\forall x\, \mathit{Fit}(x)$ means $\mathit{Fit}(\mathit{Asha}) \land \mathit{Fit}(\mathit{Bilal}) \land \mathit{Fit}(\mathit{Chitra}) \land \mathit{Fit}(\mathit{Dev})$. That view explains almost every rule below.

      The two translation rules

      “All A are B” uses $\forall$ with $\Rightarrow$: $\forall x\,(A(x) \Rightarrow B(x))$. The implication restricts the claim to the A’s; anything that isn’t an A makes the implication vacuously true, so it is ignored, which is what we want. Writing $\forall x\,(A(x) \land B(x))$ instead says that everything in the domain is an A and a B: “every player is a fit batter”, a much stronger claim.

      “Some A is B” uses $\exists$ with $\land$: $\exists x\,(A(x) \land B(x))$, a single object that is both. Writing $\exists x\,(A(x) \Rightarrow B(x))$ instead is almost always true for a silly reason: any object that is not an A makes the implication true, so it is a witness.

      Order of quantifiers matters

      $\forall x\,\exists y\; \mathit{Admires}(x, y)$: everyone has a hero, but the heroes can differ. $\exists y\,\forall x\; \mathit{Admires}(x, y)$: there is one player whom everybody admires. The second is stronger. If one player is admired by all, then certainly everyone admires somebody, so $\exists y\,\forall x \Rightarrow \forall x\,\exists y$ is valid; the reverse is not.

      Valid sentences

      A first-order sentence is valid if it is true in every world (every non-empty domain and every way of filling in the predicates). It is the first-order version of a tautology. To show a sentence is not valid, build one small world where it is false (a counter-model); two objects are usually enough.

      • Valid: $\forall x\, P(x) \Rightarrow \exists x\, P(x)$ (the domain is never empty, so “all” includes at least one).
      • Not valid: $\exists x\, P(x) \Rightarrow \forall x\, P(x)$ (one fit player doesn’t make everyone fit).
      • Valid: $\forall x\,(P(x) \land Q(x)) \Leftrightarrow \forall x\, P(x) \land \forall x\, Q(x)$, and $\exists x\,(P(x) \lor Q(x)) \Leftrightarrow \exists x\, P(x) \lor \exists x\, Q(x)$.
      • Only one direction is valid: $\forall x\, P(x) \lor \forall x\, Q(x) \Rightarrow \forall x\,(P(x) \lor Q(x))$, and $\exists x\,(P(x) \land Q(x)) \Rightarrow \exists x\, P(x) \land \exists x\, Q(x)$.

      Recall three facts from Probability 2.1. The conditional probability $P(A\mid B)$ is the chance of $A$ once you know $B$ happened. The multiplication rule says $P(A, B) = P(B)\,P(A\mid B)$, where the comma means “and”. And $A$, $B$ are independent when $P(A\mid B) = P(A)$: learning $B$ changes nothing.

      A random variable here is simply an uncertain yes/no fact, such as “it rained overnight”. We write $R$ for the fact and $R = \text{yes}$ or $R = \text{no}$ for its two values.

      Match day in the DPL

      The most complete description of five yes/no facts is a joint distribution table: one row for every combination of values, with its probability. Five facts give $2^5 = 32$ rows. The rows must add up to 1, so 31 of them are free numbers you would have to estimate from data.

      A Bayesian network has two parts.

      • A directed acyclic graph (DAG): one node per random variable, arrows between them, and no way to follow arrows round in a loop. If there is an arrow $X \to Y$, then $X$ is a parent of $Y$ and $Y$ a child of $X$. Following arrows forward from $X$ reaches its descendants.
      • For every node $X$, a conditional probability table (CPT) giving $P(X\mid \text{parents of } X)$, one row for each combination of the parents’ values. A node with no parents just stores $P(X)$.

      Each row is a probability distribution, so it adds up to 1. For a yes/no node with $k$ yes/no parents that means $2^k$ rows and one free number per row.

      A Bayesian network over $X_1, \ldots, X_n$ defines the joint distribution $$P(x_1, x_2, \ldots, x_n) = \prod_{i=1}^{n} P\big(x_i \mid \text{parents}(X_i)\big).$$ In words: the probability of a full assignment is the product of one CPT entry per node, each read in the row that matches that node’s parents.

      Why the product is the whole joint

      List the variables so that every parent comes before its children (here $R, S, L, D, F$). Using the multiplication rule over and over, any joint can be written exactly as $$P(r, s, l, d, f) = P(r)\,P(s\mid r)\,P(l\mid r, s)\,P(d\mid r, s, l)\,P(f\mid r, s, l, d).$$ That step is always true; it is the chain rule of probability. The network then adds one promise: given its parents, each variable ignores every earlier variable. So $P(s\mid r) = P(s)$, $P(d\mid r, s, l) = P(d\mid r)$ and $P(f\mid r, s, l, d) = P(f\mid l)$, and the chain rule collapses to the product of CPT entries.

      For example, the chance of the day “rain, no spinner, low score, delay, fans stay” is $$P(R, \lnot S, L, D, \lnot F) = 0.2 \times 0.4 \times 0.7 \times 0.7 \times 0.4 = 0.01568.$$ Read each factor in the row matching the parents: $P(L\mid R, \lnot S) = 0.7$ and $P(\lnot F\mid L) = 1 - 0.6 = 0.4$.

      For yes/no variables, a node with $k$ parents needs $2^k$ numbers. Add over the nodes and compare with $2^n - 1$ for the full joint. If a variable takes $m$ values, each CPT row needs $m - 1$ numbers and the number of rows is the product of the parents’ value counts.

      Conditional independence: what the arrows leave out

      Two facts can be related at first but unrelated once you know a third. If you know it rained, learning that the start was delayed tells you nothing new about whether the score will be low: all the link between them ran through the rain.

      $X$ is conditionally independent of $Y$ given $Z$, written $X \perp Y \mid Z$, when $$P(X\mid Y, Z) = P(X\mid Z)$$ for all values. Once $Z$ is known, $Y$ adds nothing about $X$. Equivalently $P(X, Y\mid Z) = P(X\mid Z)\,P(Y\mid Z)$.

      Every question about independence in a network comes down to three ways a middle node $B$ can sit between $A$ and $C$.

      The chain and the fork behave alike: information flows through the middle until you observe it. The collider is the surprise. Rain and the spinner are chosen independently, so with nothing observed they are independent.       Fix a set $Z$ of observed variables. A path between $X$ and $Y$ (following edges in either direction) is blocked if some node $B$ on it is

      • the middle of a chain or fork with $B$ in $Z$, or
      • a collider ($\to B \leftarrow$) with neither $B$ nor any descendant of $B$ in $Z$.

      If every path between $X$ and $Y$ is blocked, they are d-separated by $Z$, and then $X \perp Y \mid Z$ holds for every choice of CPTs.

      A useful special case, the local Markov property: each node is conditionally independent of its non-descendants given its parents.

      Careful: observing a descendant of a collider also opens it. In the match-day network, learning $F$ (fans left early) is evidence about $L$, so it too links $R$ and $S$.

      An inference question has three kinds of variable. The query is what you want to know ($R$). The evidence is what you have observed ($L = \text{yes}$). Everything else is hidden ($S$, $D$, $F$): not asked about, not observed.

      Recall from Bayes’ theorem (Probability 2.2) that a conditional probability is a ratio: $P(R\mid L) = P(R, L)/P(L)$. In practice you compute $P(R, L)$ and $P(\lnot R, L)$, then divide each by their sum. This last step is called normalising, and it is often written with a constant $\alpha$: $P(R\mid L) = \alpha\,P(R, L)$.

      Exact inference by enumeration

      To find $P(Q\mid e)$:

      1. For each value $q$ of the query, add the joint probability $\prod_i P(x_i\mid\text{parents})$ over every combination of the hidden variables, with the evidence held at its observed values. This gives $P(q, e)$.
      2. Normalise: divide each $P(q, e)$ by their total, which is $P(e)$.

      It is exact, but with $n$ yes/no variables it can touch up to $2^n$ rows.

      Variable elimination: enumeration without repeated work

      Enumeration recomputes the same pieces over and over. Variable elimination pushes each sum as far right as it can go, computes it once, and stores the result as a small table (a factor) for later use.

      Example: $P(F)$, the chance that fans leave early. Sum out the variables one at a time: $D$ drops out (it sums to 1), then $R$ and $S$ are summed into a factor over $L$: $$P(L) = \sum_{r, s} P(r)\,P(s)\,P(L\mid r, s) = 0.108 + 0.056 + 0.192 + 0.032 = 0.388.$$ Finally $L$ is summed out: $$P(F) = P(F\mid L)P(L) + P(F\mid\lnot L)P(\lnot L) = 0.6 \times 0.388 + 0.2 \times 0.612 = 0.3552.$$ Enumeration would have added 16 products of five factors each; elimination did four small products and one two-term sum.

      Start with one factor per CPT, with evidence values plugged in. For each hidden variable in some order: multiply together the factors that mention it, sum it out, and put the new factor back. Multiply what is left and normalise.

      The answer is exact, the same as enumeration, whatever the order. The order only changes how much work is done. It is used to compute conditional probabilities $P(Q\mid e)$ and marginals such as $P(F)$.

      Approximate inference: simulate and count

      Exact inference can still blow up on large, densely connected networks (in general it is NP-hard). The alternative is to sample: generate many random full assignments that follow the network’s probabilities, and estimate the answer as a fraction. More samples give a better estimate, but never a guaranteed exact one. That is what “approximate” means here.

      • Prior (direct) sampling. Visit the nodes parents-first. For each, toss a biased coin using its CPT row for the parent values already drawn. One pass gives one simulated match day. Example: draw $R$ with $P(R) = 0.2$; if $R$ came out yes, draw $D$ with $P(D\mid R) = 0.7$; and so on.
      • Rejection sampling. Draw prior samples and throw away every one that disagrees with the evidence. Estimate $P(Q\mid e)$ as the fraction of the kept samples with $Q$ = yes. The expected fraction kept is $P(e)$, so rare evidence wastes almost every sample.
      • Likelihood weighting. Never throw away. Fix each evidence variable at its observed value instead of drawing it, draw the others as in prior sampling, and give the sample a weight: the product of $P(e_i\mid\text{parents})$ over the evidence variables. Estimate $P(Q\mid e)$ as (total weight of samples with $Q$ = yes) ÷ (total weight).
      • Gibbs sampling (a Markov chain Monte Carlo method). Start from any full assignment that agrees with the evidence. Repeatedly pick a non-evidence variable and redraw it from its distribution given all the others, which only needs its Markov blanket: its parents, its children and its children’s other parents. Estimate by the fraction of steps with $Q$ = yes.
