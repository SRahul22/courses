      Values, lists, sets and loops: what the interpreter really does

      In Python a variable is a name attached to an object, so two names can point to the same list, and changing it through one name changes what the other sees.

      Code-tracing questions carry 4–7 marks a year and the share is growing. Most mistakes come from a few behaviours (aliasing, set algebra, simultaneous assignment, integer versus float division) that this chapter makes precise.

      It’s like two scorers sharing one scorebook: if one writes in it, the other sees the change, because there’s only one book. Making a photocopy is what A[:] does.

      Functions, scope and recursion: the questions GATE loves to trick

      A default argument is created once, when the function is defined; an inner function remembers the variables of the call that created it; and a recursive function’s work is a tree of calls you can count.

      2026 alone had three questions on exactly these behaviours (Q16, Q39, Q50), and recursion-tracing questions appear every year.

      It’s like a team kit bag handed down season after season: if one player leaves a bat in the shared default bag, the next player finds it there. Bring your own bag (pass an argument) and you start empty.

      Where it shows up in GATE DA

      Every year: tracing function calls, closures, default arguments and recursive call counts.

      2026 Q16 · mutable default argument2026 Q50 · closures2026 Q39 · counting recursive calls2025 Q63 · recursion with /2024 Q38 · counting tree nodes2024 Q41 · recursive reverse
      Heat: every year, 2–6 marks
      • Arguments are passed as references to objects. If a function mutates a list argument (lst.append), the caller sees the change. If it rebinds the name (lst = [...]), the caller doesn’t.
      • Default values are evaluated once, when the def runs. A mutable default (lst=[]) is therefore shared by every call that doesn’t pass its own list.
      • Closures: an inner function can use variables of the enclosing function. Each call of the outer function creates fresh variables, so two closures from two calls don’t share them.
      • Recursion: each call gets its own frame on the call stack with its own local variables. It returns to the caller when done.

      Complexity and binary search: counting steps that matter

      Big-O describes how an algorithm’s work grows with the input size, and binary search shows the power of halving: about $\log_2 n$ steps instead of $n$.

      Binary search has appeared in every DA paper (2024 Q40, 2025 Q27, 2026 Q31), and recurrence questions accompany the sorting algorithms.

      It’s like finding a name in a printed phone book: open the middle, decide which half, repeat. A thousand pages take only about ten looks.

      $f(n) = O(g(n))$ means $f$ grows no faster than a constant multiple of $g$ for large $n$ (an upper bound). $\Theta(g(n))$ means it grows at exactly that rate (upper and lower bound). Constants and lower-order terms are dropped: $3n^2 + 10n + 7 = \Theta(n^2)$. Growth order: $1 \lt \log n \lt n \lt n\log n \lt n^2 \lt n^3 \lt 2^n \lt n!$.

      Merge sort and quicksort: divide and conquer

      Divide and conquer splits a problem into halves, solves each recursively, and combines the answers. Merge sort does the work when combining; quicksort does it when splitting.

      Both are named in the syllabus; GATE has asked for quicksort’s swap count on a sorted array (2024 Q30) and its expected-time recurrence (2026 Q15).

      It’s like sorting a stack of scorecards with friends: split the pile, each sorts half, then merge the two sorted piles by repeatedly taking the smaller top card.

      • Node count: $H + 1 \le N \le 2^{H+1} - 1$ (a path at one extreme, a perfect tree at the other).
      • Binary search tree (BST): everything in a node’s left subtree is smaller, everything in its right subtree larger. Search, insert and delete take $O(h)$; in-order traversal lists the keys in sorted order.
      • Pre-order: node, left subtree, right subtree. (The root comes first.)
      • In-order: left, node, right. (The root splits left from right.)
      • Post-order: left, right, node. (The root comes last.)
      • Level-order: by depth, left to right (BFS with a queue).

      Reconstruction: in-order + pre-order (or in-order + post-order) determines any binary tree with distinct labels. Pre-order + post-order alone is ambiguous in general, but determines a full binary tree.

      Graph traversals: BFS, DFS and topological sort

      BFS explores a graph in rings of increasing distance using a queue; DFS dives as deep as possible before backtracking, using a stack (or recursion); a topological sort lines up a DAG’s vertices so every edge points forward.

      A traversal question appears in every DA paper: DFS edge types (2024 Q14), BFS vs DFS expansions (2024 Q44), topological orders (2024 Q51), DFS discovery order (2025 Q65), reachability in reversed graphs (2026 Q40).

      It’s like exploring a new city: BFS visits every place one stop away, then two stops away; DFS follows one road as far as it goes before backtracking to the last junction.

      • A graph has vertices and edges, either undirected or directed. The degree of a vertex is its number of edges (in-degree and out-degree for directed graphs).
      • Adjacency list: each vertex stores its neighbours; $O(V + E)$ space, best for sparse graphs. Adjacency matrix: $V\times V$ table; $O(V^2)$ space, $O(1)$ edge lookup.

      BFS: put the start in a queue; repeatedly dequeue a vertex and enqueue its unvisited neighbours. Vertices come out in order of distance (number of edges) from the start, so BFS finds shortest paths in unweighted graphs.

      DFS: visit a vertex, then recursively visit each unvisited neighbour in turn (the order of the adjacency list matters). Both run in $O(V + E)$ and visit exactly the vertices reachable from the start.
