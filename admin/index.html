1The one-minute version

courses.rahuldevsharma.com is a set of free, interactive courses: lessons, maths, widgets, quizzes and practice, each checked instantly. It is a static website: no server, no database, no sign-up. Each learner's progress stays in their own browser.

2Where things live

  • Folders. Everything website-related is in ~/Dev: courses/ (the live site, built output only), course-sources/<course>/ (one source folder per course), tools/ (shared Python venv and puppeteer, KaTeX, fonts), claude/ (the course-site skill and Claude's memory), pages/ (unpublished side pages), archive/ (superseded things awaiting review). Lecture materials stay in OneDrive and are read in place.
  • Repos (GitHub user SRahul22). Public: courses = the live site. Private: dev-workspace (~/Dev itself) and one per course: gate-da, downhill, tour-guide, inventory, achuthan-cvrp, head-start.
  • Hosting. GitHub Pages serves SRahul22/courses, branch main; the CNAME file names the domain. It rebuilds a minute or two after each push.
  • Domain. rahuldevsharma.com, DNS at Squarespace Domains. courses is a CNAME to srahul22.github.io; keep the _github-pages-challenge-SRahul22 TXT record. www is the Google Sites personal page.

3How a course is built and published

Every course comes from the course-site template: parts and chapters written as HTML in source/parts/, an engine in source/js/core.js, widgets in js/w_*.js, one shared look (design v5: cool paper, ink blue, coral, Figtree and Source Serif 4). Every number in the content is checked in Python first. GATE DA is the same idea split into a hub plus one page per module. The commands, run in the course's source folder:

# 1. build into ~/Dev/courses/<path>/
python3 source/build.py
# 2. test (screenshots go to a scratch folder, never into ~/Dev/courses)
NODE_PATH=~/Dev/tools/node_modules node source/test/check.js all /tmp/shots --solve
NODE_PATH=~/Dev/tools/node_modules node source/test/cert.js /tmp/cert
# GATE DA also: python3 source/test/audit_keys.py and
#   ~/Dev/tools/venv/bin/python source/test/vary_check.py
# 3. publish the live site: add only the folder you changed (and refresh the sitemap for search engines)
cd ~/Dev/courses && git pull --rebase && python3 ~/Dev/tools/sitemap.py
git add <path> sitemap.xml robots.txt && git commit -m "…" && git push
# 4. back up the source
cd ~/Dev/course-sources/<course> && git add -A && git commit -m "…" && git push

Publish progressively and safely. Push each piece as soon as it is tested. Safe means the course's checks pass, saved progress can't be lost, and unrelated files are left alone. Never git add -A in ~/Dev/courses. Untested work stays on a branch. To undo a bad publish: git revert <commit> in ~/Dev/courses, then push.

Preview locally: python3 -m http.server 8770 --directory ~/Dev/courses, then open http://localhost:8770/.

4Learners' data

There are no accounts. Progress, review dates and streaks sit in each visitor's browser localStorage, under a prefix per course: gateda-…, downhill-…, tourguide-…, restock-…, achcvrp-…, first-commit-progress-v2… (HEAD Start). Light or dark mode is one shared key, courses-theme.

Iron rule. Never rename a storage key, a question data-id or a URL. Only append new questions to the end of a quiz, because quiz ids are positions. Break this and learners silently lose their progress.

5Working with Claude

Open Claude Code at ~/Dev. It reads ~/Dev/CLAUDE.md, which sends it to ATLAS.md, the map of everything. For a course, it should also read that course's HANDOFF.md (GATE DA) or README.md and CLAUDE.md. Memory in ~/Dev/claude/memory/ keeps the owner's preferences. Parallel sessions work in separate git worktrees. A good opening prompt:

Read ~/Dev/ATLAS.md and course-sources/gate-da/HANDOFF.md, then run
python3 ~/Dev/atlas.py and tell me what's unpushed. Then: <the task>.
